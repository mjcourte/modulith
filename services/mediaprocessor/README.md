# Media Processor

Wraps `ffprobe` (and later ffmpeg).

- **Probing** (built 2026-10-12): `Prober.Probe(ctx, url)` reads a video or audio file's metadata over HTTP range requests from a presigned URL and returns `Info`. Storage calls it from its probe job (storage README, "Media metadata"); mediaprocessor never calls storage (no cycle, no "report back"). It has no schema and no state.
- **Layout**: `mediaprocessor.go` is the public surface (aliases, `NewFFprobe`, `RegisterGRPC`, `NewGRPCClient`); `internal/probe` runs ffprobe and normalises its output; `internal/grpcapi` is `MediaProcessorService` (`contracts/proto/gyoza/mediaprocessor/v1`).
- **How ffprobe runs**: `ffprobe -v error -protocol_whitelist https,tls,tcp[,http for local RustFS] -probesize ... -analyzeduration ... -show_entries ... -of json -- <url>`, under a timeout. The probe limits bound how much is read; it never downloads the whole file. `NewFFprobe` finds ffprobe at startup (`exec.LookPath`).
- **Isolation**: the risk is a crafted file exploiting ffprobe and reaching what its process can. So the child gets an empty environment (only `PATH`, plus `SYSTEMROOT`/`TEMP` on Windows), never ours, so it can't see `GYOZA_S3_*` or `GYOZA_DATABASE_URL`; the protocol whitelist stops it opening local files such as `.env` or other URLs. `cmd/mediaprocessor` reads no secrets, and its container has no database or S3 settings. The monolith accepts the remaining risk (an exploit reading files as our user) for local dev and the MVP. Both safeguards are tested and mutation-checked.
- **`Info`**: normalised from ffprobe's JSON (`ProbeResult`, unexported): display `Width`/`Height` (after rotation; 0 = unknown), `Duration`, `BitRate`, `Format`, and `Video`/`Audio` streams (codec, size, frame rate, rotation; sample rate, channels, bit rate; a video can have several audio tracks). Codecs stay strings: allow-lists belong where support matters (the engine). Images aren't probed here: storage reads their headers itself
- **ffprobe's quirks**: frame rates are rationals (`"30000/1001"`, `"0/0"` = unknown); durations can be `"N/A"` or missing (the stream's is used instead); rotation comes from stream side data, and ±90 swaps the display size
- **Errors**: `ErrNoMedia` (no audio or video streams); `ErrUnavailable` (the gRPC client couldn't reach the service: retry later, not the file's fault, so storage doesn't count it as an attempt). Other failures carry ffprobe's message with the URL removed, over gRPC too, since storage records it on the file.
- **Running**: in-process in the monolith when ffprobe is on PATH (it warns and skips probing otherwise); standalone `cmd/mediaprocessor` (`localhost:9092`) for distributed mode, with its own container image (`Dockerfile` target `mediaprocessor`, with ffprobe). Verified end to end: a video uploaded through the storage container probed `ready`; with mediaprocessor stopped it stayed `pending` with no attempts used, then probed once it was back.
- **Tests**: `toInfo` table tests on captured ffprobe JSON (portrait with rotation, landscape); `ffprobe_test.go` probes `testdata/tiny_rotated.mp4` over `httptest` (skips without ffprobe); gRPC round trip and error mapping over `bufconn` (mutation-checked 5/5).
